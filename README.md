# Прототип административного интерфейса Aurora v10

Интерактивный прототип административной модели Aurora Corporate v10 предназначен для проверки состава функций, связности сценариев и понятности интерфейса. Это не рабочая клиентская часть и не новый нормативный программный интерфейс (API).

## Точки входа

- `tenant-admin.html` — раздел «Настройки → Организация» для администратора организации;
- `provider-console.html` — отдельная консоль провайдера, реселлера и администратора платформы;
- `self-hosted-admin.html` — стабильный вход для оценки самостоятельной установки без параметра `?multi=off`; он открывает область установки и оставляет только области установки, провайдера и дефолтной организации.

Между тенантской и провайдерской поверхностями нет продуктового переключателя. Третий файл не создаёт новую продуктовую поверхность: это отдельная прототипная оболочка того же режима провайдерской консоли, необходимая для стабильной ссылки, передачи набора файлов и обновления страницы после изменения общих ресурсов. Микроприложение организации не загружает маршруты или подготовленные данные провайдера.

## Публичная проверка

Последнее успешно опубликованное состояние ветки `main` доступно без локального сервера:

- [консоль провайдера](https://afterlogic.github.io/aurora-x-admin-prototypes/provider-console.html);
- [администрирование организации](https://afterlogic.github.io/aurora-x-admin-prototypes/tenant-admin.html);
- [самостоятельная установка](https://afterlogic.github.io/aurora-x-admin-prototypes/self-hosted-admin.html).

Закрытый исследовательский репозиторий сохраняет исходники и историю решений. После изменения административных прототипов в его ветке `main` автоматизация заменяет содержимое отдельного публичного репозитория `afterlogic/aurora-x-admin-prototypes` только файлами этого каталога и служебным пустым файлом `.nojekyll`. Узкий ключ развёртывания может записывать только в публичную витрину; витрина не получает ключ, документы закрытого репозитория, производственные данные или подключения к рабочим системам. Успешная публикация не заменяет локальную браузерную матрицу и независимый аудит незакоммиченного различия.

## Основная модель

У управляемого изменения один последовательный путь:

```text
область действия → источник итогового значения → черновик → проверка
→ предварительный просмотр последствий → подтверждение → результат → аудит → восстановление
```

Простое действие «Сохранить» применяется только к обратимым локальным предпочтениям. Изменения безопасности, лицензий, подготовки ресурсов, внешних систем и удаление проходят явное подтверждение с последующим показом результата.

| Раздел | Экраны | Назначение |
|---|---|---|

| Люди | `ADM-USERS-001`, `ADM-USER-001`, `ADM-DEPROVISION-001`, `ADM-GROUPS-001` | Жизненный цикл пользователей и групп. |

| Безопасность и устройства | `ADM-SSO-001`, `ADM-MOBILE-001` | Делегированные настройки единого входа, безопасности и мобильных устройств. |
| Брендирование и ИИ | `BRAND-EDITOR-001` со встроенным представлением `BRAND-PREVIEW-001`, `AI-POLICY-001` | Единый экран профиля брендирования и ограничивающая политика ИИ. |
| Активность и состояние | `ADM-AUDIT-001`, `ADM-STATS-001`, `TEN-SUPPORT-001`, `ADM-OPS-001` | Аудит, показатели, согласие на доступ поддержки и результаты операций. |

Видимость каждого пункта определяется итоговым снимком возможностей и разрешений. Отсутствующий пункт не заменяет серверную авторизацию. Администратор организации не получает данные других организаций, привязки и лицензии провайдера, создание сеансов поддержки, резервное копирование, клиентов подготовки ресурсов или расширения.

## Общие схемы взаимодействия

| Схема | Обязательное поведение |
|---|---|
| Список с подробностями | Выбор сохраняется по устойчивому идентификатору; смена области очищает устаревший выбор и данные. |
| Черновик → проверка → просмотр → публикация | Неверный черновик не заменяет действующую версию; публикация подтверждается сервером и записывается в аудит. |
| Проверка внешней системы | Ожидающий и неопределённый результаты отличаются от успеха; при проблеме доступен код для службы поддержки и повтор проверки. |
| Разрушительное действие | Видны точный объект, область, последствия, подтверждение, ход операции и частичный результат. |
| Редактор итогового значения | Вместе видны происхождение значения, блокировки, допустимый диапазон, черновик и действующая версия. |
| Передача в поддержку | Не показываются секреты, содержимое и необработанные журналы; при проблеме можно скопировать код для службы поддержки. |

## Утверждённые границы версии 1.0

- У каждой организации ровно один `BrandProfile` — профиль брендирования (Brand Profile); множественные профили внутри одной организации отсутствуют.
- Организация меняет разрешённые название, цвета и логотип. Провайдер управляет назначенным провайдером именем узла доступа, DNS, TLS и включением маршрута.
- Почтовый домен и имя узла доступа — разные сущности. Принадлежащие организации маршруты доступа отсутствуют в v1.0.
- OIDC и SAML образуют базовый контур единого входа (SSO). Единый вход Windows через IWA выполняет вышестоящий поставщик удостоверений (upstream IdP) или доверенный посредник аутентификации; Aurora принимает и проверяет стандартное утверждение.
- Внешние приглашения календаря и внешние ссылки на файлы реализованы в v1.0. Политика провайдера или организации может ограничить их использование, но не заменяет отсутствующую возможность.
- Итоговая доступность функции вычисляется сверху вниз: глобальная политика провайдера → тариф и набор возможностей → политика организации → разрешение субъекта → доступность во время выполнения.
- Эксплуатационная телеметрия, встроенные журналы Aurora, аудит приложения, статистика использования, диагностика и свидетельства операций являются разными договорами данных. Внешняя система наблюдения и SIEM дополняют базовый встроенный просмотр, но не являются обязательными для самостоятельной установки заказчика.
- Необязательный доступ агентов в v1.0 работает только для чтения. MCP служит адаптером к тем же службам административных запросов, с отдельной служебной учётной записью, точной областью, набором средств, классами данных, ограничениями и аудитом каждого вызова.

## Языковая политика

- Внутренние ТЗ, рабочие решения и описания прототипов ведутся на русском языке. При первом формальном упоминании термин обязательно даётся по-русски, а канонический английский эквивалент указывается в скобках.
- В русской локализации видимый интерфейс использует русский язык. Исключения: собственные имена, адреса и домены, утверждённые технические аббревиатуры и явно обозначенные машинные значения.
- Публичные материалы для разработчиков и описание программного интерфейса публикуются только на английском языке по DR-0023.
- Документация администратора и администратора организации имеет канонический английский источник и переводится на утверждённые языки интерфейса.

## Устройство прототипа

- `provider-console.html`, `self-hosted-admin.html` и `provider-console.bootstrap.js` — две стабильные оболочки общей консоли для мультитенантного и самостоятельного режимов без копирования манифеста или рендерера;
- `tenant-admin.html` — проверочный узел, имитирующий место монтирования в пользовательском приложении;
- `tenant-admin.microfrontend.js` — явный договор `mount(host, options)` и `unmount()`; при размонтировании удаляются обработчики, таймеры и DOM;
- два файла `*.manifest.js` — независимые манифесты маршрутов и данных;
- `admin-capabilities.js` — единственный владелец материализации итоговой модели: элементы запрещённых возможностей удаляются до монтирования интерфейса;
- `admin-demo-state.js` — единый владелец связанных демонстрационных состояний интеграций провайдера и организаций;
- `admin-core.js` — общий владелец состояния, основное средство отрисовки и единый путь событий;
- `admin.css` — общие переменные оформления и адаптивная геометрия.

Над оболочкой реального интерфейса постоянно находится панель «Прототип · служебные настройки». Переключатель «Показывать служебные сообщения» по умолчанию выключен; при включении средство основной отрисовки добавляет номера экранов, операции, внутренние версии, пояснения ТЗ и селекторы демонстрационных состояний. Флажок «Показать элемент в альтернативном состоянии» доступен только на маршрутах с утверждённым детерминированным сценарием и не изменяет основной пример. Отдельный выключенный по умолчанию переключатель «Показывать службы каталогов» существует только над тенантской админкой и позволяет проверить отсутствие или наличие подключаемой возможности. В консоли провайдера этого проверочного переключателя нет: провайдер использует реальное действие «Разрешить» или «Запретить» для выбранной организации. Переключатель плотности не входит в утверждённый прототип.

Для проверки доступны два синтетических профиля: `?profile=business` содержит 16 маршрутов без ИИ и поддержки, а `?profile=managed` — 18 маршрутов с обеими условными возможностями. Встроенный предварительный просмотр брендирования учитывается отдельным идентификатором трассировки, но не является маршрутом. В продукте сервер отдаёт единственную итоговую конфигурацию текущего субъекта; эти профили не являются границей безопасности.

## Локальная проверка

`file:///` не является допустимой точкой входа для проверки в браузере. Используется только локальный HTTP-адрес `http://127.0.0.1:<port>` или `http://localhost:<port>`.

Из корня текущего рабочего каталога прототип можно запустить так:

```powershell
py -B -m http.server 8769 -b 127.0.0.1 -d prototypes/aurora-v10-wireframes/admin
```

Проверяющий подтверждает ответ HTTP 200 для обеих точек входа, после изменений выполняет полную перезагрузку, а по завершении останавливает HTTP-процесс. Порт и фактические результаты проверки фиксируются в рабочем задании.

## Контрольный список

- Все маршруты доступны только на разрешённой поверхности.
- Служебные сообщения отсутствуют из DOM реального интерфейса до включения внешнего переключателя.
- Переключатель плотности и отдельный пункт предварительного просмотра брендирования отсутствуют.
- Действия соответствуют каталогу экранов и карте операций.
- DOM организации не содержит маршрутов или данных провайдера.
- Полное значение обрезаемого текста можно увидеть и скопировать.
- Узкая компоновка сохраняет основное действие и видимый путь прокрутки.
- Диалоги закрываются клавишей Escape, возвращают фокус и очищают временное состояние.
- Первичная отрисовка и переходы не создают неперехваченных ошибок консоли.
- Почтовый прототип и его проверки не изменены.
